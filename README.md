# InvoiceMaker

Личный Telegram-бот: создаёт акт и счёт в Excel по месячным листам Google Таблиц.
Доступ разрешён одному владельцу по числовому Telegram ID, только в личном чате.

## Возможности

- Актуальный список листов при выборе месяца и предпросмотр перед созданием.
- Два XLSX по шаблонам: акт с работами и ссылками, счёт с итогами по ставкам.
- Настройки договоров, реквизитов, срока оплаты и следующего номера в Telegram.
- Неизменяемые версии документов в SQLite и повторное скачивание из архива.
- Отдельное скачивание акта и счёта: если Telegram задержал отправку одного файла,
  второй всё равно отправляется, а недостающий можно получить из архива.
- Проверка изменения таблицы между предпросмотром и подтверждением.

Денежные расчёты выполняются через Decimal. Google-таблица используется только для чтения.
Дата документа — день формирования в часовом поясе таблицы. Оплата по умолчанию до
10-го числа того же месяца; прошедший срок нужно изменить в предпросмотре.
Следующий номер — любое положительное целое, включая меньшее или повторное.
Новый лист получает выбранный номер, затем он увеличивается на 1. Повторное оформление
того же листа сохраняет его номер и создаёт новую архивную версию. Ошибка не расходует номер.
Меню архива показывает последнюю версию каждого месяца; предыдущие остаются в базе.

## Требования и таблица

Python 3.12 или Docker с Docker Compose. Нужны свой бот из @BotFather, числовой Telegram ID,
служебный аккаунт Google с включённым Google Sheets API и таблица, доступная ему на чтение.
Каждый месяц — отдельный лист, первая строка содержит колонки A:F:

| A | B | C | D | E | F |
|---|---|---|---|---|---|
| Ссылка на задачу | Наименование | Количество часов | Стоимость часа | Сумма | Комментарий |

Считывается весь диапазон A:F. Пустые строки с одной ставкой и нулевой суммой пропускаются.
Ошибочные заполненные строки и расхождения сумм блокируют создание с указанием строки.
Тексты ячеек не исполняются как инструкции или формулы.

## Настройка

```bash
git clone https://github.com/Pronik52/botInvoices.git
cd botInvoices
umask 077
mkdir -p secrets data
cp .env.example .env
cp defaults.example.json defaults.json
cp templates/examples/act.xlsx templates/act.xlsx
cp templates/examples/invoice.xlsx templates/invoice.xlsx
```

Заполните `defaults.json`: ID таблицы (часть ссылки между `/d/` и `/edit`), реквизиты,
первоначальный договор. Нулевые реквизиты примера — заглушки, замените их своими.
В каталог `secrets/` поместите:

| Файл | Содержимое |
|---|---|
| `telegram-token` | Токен бота одной строкой |
| `telegram-owner.json` | JSON вида `{"user_id": 123456789}` с вашим Telegram ID |
| `google-service-account.json` | JSON-ключ служебного аккаунта Google |

Предоставьте таблицу на чтение адресу `client_email` из ключа Google.

```bash
chmod 700 secrets data
chmod 600 secrets/* defaults.json .env
```

В `.env` можно указать `EXPECTED_BOT_USERNAME` без `@` для проверки принадлежности токена
нужному боту, а также пути к настройкам, секретам и шаблонам. Токен и ключ Google
читаются из файлов, а не из `.env`.

**Примеры XLSX не содержат подпись:** вместо неё оставлено прозрачное изображение.
Замените его своей подписью в личных копиях через Excel. Сохраняйте расположение ячеек:
генератор рассчитан на приложенный макет. Для другого макета измените адреса в
`invoice_maker/documents.py`. Формулировки НПД и НДС проверьте на соответствие своим документам.

## Запуск

```bash
sh deploy.sh
```

Скрипт создаёт приватную папку данных, задаёт UID/GID текущего пользователя и запускает
только сервис `bot`. Если Docker недоступен пользователю, используется `sudo -n`.
Для прямого запуска `docker compose up -d --build` сначала укажите в `.env` UID/GID
владельца `data/` (команды `id -u` и `id -g`).

```bash
docker compose ps
docker compose logs --tail=50 bot
docker compose restart bot
```

При необходимости добавьте `sudo` перед Docker. Входящих портов нет: используется long polling.
Перезапуск автоматический (`unless-stopped`), база находится в `data/` вне контейнера.
Лимит памяти — 160 МБ; для больших документов его можно изменить в `compose.yaml`.

Без Docker:

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.lock
CONFIG_DIR="$PWD/secrets" DATA_DIR="$PWD/data" .venv/bin/python -m invoice_maker
```

Без Docker `.env` автоматически не читается. Дополнительные переменные задавайте
в оболочке или менеджере процессов.

## Использование

`/start` → **Создать акт и счёт** → месяц → проверить данные → **Создать два Excel-файла**.
В **Настройках** доступны реквизиты, договоры, следующий номер, день оплаты и услуга.
По умолчанию выбирается последний договор по дате. Ручной выбор сохраняется при добавлении
нового договора; отдельная кнопка возвращает автоматический выбор.

`defaults.json` загружается только при создании новой базы. Для работающего бота меняйте
реквизиты в Telegram. Не удаляйте базу ради смены настроек: в ней хранится архив.

## Резервная копия

Согласованная копия работающей SQLite-базы:

```bash
umask 077
mkdir -p backups
python3 - <<'PY'
import sqlite3
from datetime import datetime
with sqlite3.connect('data/invoice-maker.sqlite') as source:
    with sqlite3.connect('backups/invoice-maker-' + datetime.now().strftime('%Y%m%d-%H%M%S') + '.sqlite') as target:
        source.backup(target)
PY
```

Автоматическая внешняя копия не настраивается. При переносе сохраните базу, личные шаблоны,
настройки и секреты. Восстанавливайте базу при остановленном боте.

## Разработка

```bash
.venv/bin/python -m unittest discover -s tests
```

Тесты работают без ключей Google и Telegram. В чистом репозитории используются обезличенные
шаблоны из `templates/examples/`; при наличии личных шаблонов тестируется их макет.

| Модуль | Назначение |
|---|---|
| `domain.py` | Разбор строк и денежные расчёты |
| `sheets.py` | Чтение Google Sheets |
| `store.py` | Настройки, договоры, нумерация, архив, миграции SQLite |
| `documents.py` | Редактирование XML внутри XLSX с сохранением макета |
| `workflow.py` | Предпросмотр и проверка актуальности данных |
| `bot.py` | Диалоги и кнопки Telegram |
| `__main__.py` | Загрузка подключения и запуск |

`.env`, личные реквизиты, подписи, секреты и база исключены из Git.
В образ Docker попадают только примеры; личные файлы подключаются при запуске.
Подробнее: [конфигурация и данные](doc/setup.md).
